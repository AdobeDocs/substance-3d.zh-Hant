# 貢獻文章

我們歡迎來自我們社群以及來自文件團隊外的 Adobe 員工的貢獻。

## Adobe 開源行為準則

本專案已採用 [Adobe 開源行為](code-of-conduct.md) 準則或 [.NET 基金會行為](https://dotnetfoundation.org/code-of-conduct)準則。 欲了解更多資訊，請參閱貢獻[&#128279;](contributing.md)文章。

## 如何貢獻 Adobe 內容

**如果你不是 Adobe 員工** ，可以提交外部社群貢獻。 社群貢獻會匯入我們的內部系統，並在公開倉庫中編輯與合併。 公開倉庫會與最新變更同步並合併到私人倉庫。

**如果你是 Adobe 員工**，可以直接貢獻到 Adobe 的私人 [GitHub 倉庫](https://git.corp.adobe.com/AdobeDocs/)。 詳情請參閱 Adobe 員工的 Adobe Experience League 創作指南。

## 外部貢獻者

### 小幅變動

如果你只是提供小更新：

1. 請直接切換到你想編輯的主題。
1. 在「這些內容有幫助嗎？」這個主題中。 點擊瀏覽器視窗底部的橫幅，點擊 **詳細回饋選項**。
1. 點擊 **建議編輯** ，並在 GitHub UI 提交你的修改拉取請求（PR）。

   更多資訊請參閱一般 [Adobe Docs 貢獻者指南](https://experienceleague.adobe.com/docs/contributor/contributor-guide/introduction.html) 。

您在本資料庫中提交的文件與程式碼範例所提交的輕微修正或澄清，均受 Adobe 使用條款約束。

### 社群中重大變動或新主題

如果你是 Adobe 社群的一員，想建立新主題或提交重大變更，請使用 **該 Git 倉庫中的「問題** 」標籤，提交議題，開始與文件團隊的對話。 一旦計畫達成共識，你將與 Adobe 寫手合作，將修訂內容發佈。

**注意：** 如果你提交包含文件和程式碼範例重大變更的拉取請求，你會在拉取請求中看到訊息要求你提交線上貢獻授權協議（CLA）。 我們需要您填寫線上表單，才能審核您的拉取請求。

### 工具

社群貢獻者可以使用 GitHub 介面進行基本編輯，或分支倉庫以做出重大貢獻。

詳情請參閱 [Adobe 文件貢獻者指南](https://experienceleague.adobe.com/docs/contributor/contributor-guide/introduction.html) 。

## 內部貢獻者

如果你是 Adobe Experience Cloud 解決方案產品團隊的技術寫手、專案經理或開發者，且你的工作是貢獻或撰寫技術文章，請使用 [私人倉庫](https://git.corp.adobe.com/AdobeDocs)。

## 格式化你的主題

這個倉庫裡的所有文章都使用 GitHub 風格的 Markdown。 如果你不熟悉 Markdown，請參考：

* [Markdown 基礎](https://help.github.com/articles/getting-started-with-writing-and-formatting-on-github/)
* [可列印的折扣速查單](https://guides.github.com/pdfs/markdown-cheatsheet-online.pdf)

## 唱片公司

在公開倉庫中，自動標籤會被分配給拉取請求，以協助我們管理拉取請求的工作流程，並讓你知道拉取請求的狀況：

* **變更已發送給作者**：作者已收到待處理的拉取請求通知。
* **準備合併**：我們的拉取請求審查團隊已準備好審核。
